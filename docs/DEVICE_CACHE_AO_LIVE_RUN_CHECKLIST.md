# TEST checklist: device cache and offline read-only view (ao), branch `claude/device-cache-ao`

Run on TEST (_Testing workbook): Actions -> "Deploy to GitHub Pages" -> branch `claude/device-cache-ao`. The TEST bar must read `TEST · claude/device-cache-ao`. Steps 1-3 (Stage 1) were run on build 102 (results in docs/BACKLOG.md (ao)); steps 4-12 are for this build (Stages 2-3). Everything below is on the S25 unless marked.

Two timing rules that explain what you will see:
- The app saves a copy only after a full read of a workbook that was last changed MORE THAN 2 MINUTES before the read. Right after any edit (yours, Copilot's or the app's), the next read is used but no copy is saved; a later read saves it.
- A launch trusts the copy only if the workbook has not changed in the LAST 10 MINUTES. Within 10 minutes of any edit, a launch shows the copy briefly and then re-reads the workbook.

So for steps 5 and 6, leave the workbook alone for at least 10 minutes first.

4. First launch of this build (a new build deletes any old copy). Open the TEST build normally. Expect: the usual splash. On the Docket, at the bottom: "Data: read from the workbook HH:MM", "Launch read (…): 11 of 11 sheets, …". If you tested within the last few minutes, swipe the app away, wait 3 minutes and open it again before step 5 (so a copy gets saved).
5. Launch from the copy. Swipe the app away and open it again (workbook untouched for 10+ minutes). Expect: the splash goes noticeably faster. Docket: "Data: checked with the workbook HH:MM (saved copy matched)", "Saved copy at launch (…): matched the workbook in X s; no sheet reads", "Launch read: none (the saved copy was used)". Browse, Albums and a coin's details look as usual. Edit Coin works (its Save is not dimmed).
6. A change made elsewhere, at launch. Swipe the app away. In Excel, change something visible on a _Testing coin (for example its Remarks). Open the app right away. Expect: a gray row "Saved copy from … · updating from the workbook…" for a second or two, then it goes; the coin shows the new value. Docket: "Saved copy at launch (…): workbook changed; re-read". Put the Excel value back.
7. A change made elsewhere while the app is open. With the app open, change a coin in Excel. Switch to another app for at least a minute, then come back. Expect: toast "Updated from the workbook" and the new value. Put it back.
8. Offline with the app open. Turn on airplane mode with the app open. Expect: an amber row "Offline · read-only · data from …" (or "· saved copy from …"). Browse, Albums and details still work (photos may not). Edit, Add Coin, the Docket's Promote / Re-check buttons look dimmed; tapping one says "Read-only while offline" and nothing opens. If an Edit Coin form was already open: change a field and tap Save: "Offline: nothing was saved. Your changes are still on this screen; Save again when back online." and the change is still in the form. Turn airplane mode off. Expect: within a few seconds (at most about 30) the row goes, toast "Back online · data is current" (or "· updated from the workbook"); Save now works.
9. Offline cold start. Airplane mode on, swipe the app away, open it. Expect: the browser's own "no internet" page. This is the known limit (no service worker, backlog (at)), not a bug. Airplane mode off.
10. A save clears the copy, and where the save time goes. Edit Coin on a _Testing coin, change Notes, Save. On the Docket: "Last save (…, Edit Coin AY-…): N s, done, N steps"; open "Save steps" and screenshot it (this is the 12-15 s breakdown Ray asked for). Then swipe the app away and open it: Docket says "Data: read from the workbook …" (the save deleted the copy; the version also changed).
11. (Optional, desktop Chrome on the TEST URL) DevTools > Application > IndexedDB: only `salty-cabinet-cache-copy`, with one record `workbook`.
12. After the merge and a LIVE deploy (later, not now): the first LIVE launch says "Data: read from the workbook …" (never TEST's copy; the TEST database is deleted at that launch) and there is no TEST bar.

Also worth a screenshot if it happens: a slow or failed launch (for example at work). The Docket's launch line now lists every failed attempt with its time and reason (timeout / auth / HTTP …) and the launch total. "Can't reach OneDrive · read-only · … · Retry" is the amber row when the phone is online but OneDrive does not answer; Retry checks again.
